# SYRD-247: Zorin test19 image-paste handoff

This handoff is for a Claude or Codex instance **running inside the Zorin VM**. Diagnose and fix the live clipboard path there. The remote Director cannot observe that VM's compositor or tenant process environment and should not ask the User for another series of process captures. The User has spent three weeks trying to complete an end-to-end launch; preserve the working `test19` tenant and make this the last targeted investigation before asking for another acceptance run.

## What is known

- `test19` was provisioned after the SYRD-246 fix. Its viewer opened all five roles in the correct 3-over-2 layout: designer, director, audit above; main and ops below. Claude and Codex reached their ordinary prompts. The User confirms focus and resize work.
- Pasting a known image fails in both provider families. Claude briefly says **“no image in clipboard”**. Codex says **“Failed to paste image: clipboard unavailable: Unknown error while interacting with the clipboard: X11 server connection timed out because it was unreachable.”** This fails item 7 of the authoritative acceptance ticket, SYRD-222. The presentation is otherwise usable.
- Public Switchyard `main` was `3620184c28be8b4c9aba32efaf1b0c729b290219` when this handoff was written. Verify `switchyard --version` **inside Zorin** before attributing behavior to that tree; the screenshot does not prove the installed commit.
- SYRD-98 is a related, deferred **Codex-only** clipboard ticket from another host. Its live process lacked `DISPLAY`, `WAYLAND_DISPLAY`, `XDG_RUNTIME_DIR`, and `DBUS_SESSION_BUS_ADDRESS`, causing Codex to fall back to unreachable X11. Do not assume that is also the Zorin root cause: Claude fails here too. Read SYRD-98's existing security constraints before designing a transport.
- The project policy is described in `docs/desktop-access.md`. `scripts/desktop_access.py` verifies a GUI-owned readiness receipt, socket identity, ACLs, and tenant socket access. `prepare_project_desktop()` in `scripts/team_launcher.py` constructs role environments: an absolute `WAYLAND_DISPLAY` pointing at the approved GUI socket, the tenant's `XDG_RUNTIME_DIR` and bus, and no inherited `DISPLAY`/`XAUTHORITY`. Those are intended semantics, not proof that the live role processes received them.

## First local investigation

1. Keep the existing `test19` viewer and sessions. Do not create `test20`, tear down `test19`, log out the GUI user, restart every role, or change ACLs just to gather evidence. Establish the installed Switchyard release, the declared desktop policy for `test19`, the active GUI session type, and the owner of the clipboard and provider processes.
2. Have the User deliberately copy a harmless known image to the Zorin desktop clipboard. Check **MIME types and availability**, first as the GUI owner and then as `test19-agent` with the environment that a live role actually inherited. Do not dump unrelated clipboard contents into logs, tickets, chat, or test fixtures. If image bytes are needed, use only the deliberately copied test image, a private temporary file, and cleanup.
3. Inspect the live Claude and Codex child process environments for only these keys: `WAYLAND_DISPLAY`, `XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS`, `DISPLAY`, and `XAUTHORITY`. Compare them with the generated `test19` policy and the values returned by the desktop verifier. Do not paste full `/proc/*/environ`, tokens, credential files, or provider config. Confirm whether the approved Wayland socket remains accessible **as the tenant** after launch, not merely whether its pathname exists.
4. Separate the cases: (a) the GUI clipboard has no image MIME; (b) the tenant cannot read the known image despite a successful prelaunch socket probe; (c) tenant-level image access works but a provider chooses a different clipboard backend or shortcut; (d) presentation/tmux input intercepts the paste action. Test Claude and Codex independently, using their actual image-paste gestures. Ordinary text paste is a separate control and must continue to work.
5. Trace the responsible code and the smallest safe correction. Start with `docs/desktop-access.md`, `scripts/desktop_access.py`, `scripts/team_launcher.py` (`prepare_project_desktop`, role environment construction, and viewer launch), `tests/desktop_access_test.py`, and `tests/team_launcher_env_config_test.py`. Search for existing image/clipboard handling before adding a new path. The Codex error is evidence of an X11 fallback, not proof that merely setting `DISPLAY` is safe or sufficient.

## Boundaries and acceptance

- Preserve the declared desktop policy and process authority. Do not export the GUI owner's full environment, copy Xauthority or credentials, run `xhost +`, broadly chmod sockets, or give every same-UID role an unreviewed reusable clipboard/compositor capability. If provider-native clipboard access cannot work within the current authority model, design a narrow desktop-owned, user-mediated image handoff as SYRD-98 describes: bounded image data, validated type and size, no caller-selected file path, no general clipboard-read endpoint, cleanup, and refusal of an unregistered/stale runtime.
- Add focused tests for the boundary changed. Reuse existing passing test evidence; do not rerun large suites just because they exist. Verify live with the known image: it appears as an image attachment in at least one Claude pane **and** one Codex pane, with no X11 timeout or “no image” message. Then verify ordinary text paste, viewer close/reattach, and an idle affected-role restart without losing image paste. Keep focus, resize, layout, and scrollback intact.
- Record the exact installed release, reproduction, root cause, changed files, focused test output, and live result. If a fix is made in the Zorin checkout, commit it on a topic branch and create a `git format-patch -1` file under `/tmp` so it can be transferred back; **GitHub push from Zorin is not required**. Do not mark SYRD-222 accepted until the User completes its remaining reattach and reversible suspend/start checks and explicitly signs off.
