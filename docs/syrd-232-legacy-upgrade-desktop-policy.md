# A legacy upgrade that did not ask for its desktop policy

Live on mefp, 2026-09-22. The root-run upgrade completed artifacts, accounts,
identities and the release deploy, closed its journal and reported no remaining
Director phase. The operator then did the documented pane restart.
`switchyard stop mefp` suspended the roles, listener and board cleanly;
`switchyard start mefp` brought the board and listener back and refused to launch
a single role:

```
switchyard: desktop setup incomplete before launch: Choose a desktop policy
before launch: --desktop-policy FILE with mode headless or wayland.
```

The requirement is right. Wayland access is per tenant and cannot be inferred
from another project, and headless is a choice somebody has to make rather than a
default to pick for them. What was wrong is when it was first mentioned: after a
working tenant had been suspended.

## Why the upgrade said nothing

`upgrade_project_command` looked at the desktop policy only when one was supplied
or already recorded:

```python
if desktop_policy is not None or config.desktop_access is not None:
    config = configure_project_desktop(...)
```

A legacy tenant, provisioned before desktop policies existed, has neither. The
block was skipped, silently, and the upgrade carried on and declared its
artifacts prepared.

Reproduced against a tenant generated by the real provisioning code with its
policy removed: the upgrade exited 0, said nothing about a desktop, ended on
"generated artifacts are prepared", and `prepare_project_desktop` — what
`switchyard start` runs — then refused with the live message word for word.

## Asked first

The upgrade now decides the desktop policy before anything else: before the
pinned release is recorded, before the owner's user manager is repaired, and
before any phase. That placement is deliberate. Some phases restart roles
themselves — the identities transaction restarts every role against the staged
bundle — so a missing policy discovered part-way could strand roles down in the
middle of an upgrade. Asked first, the answer costs nothing and changes nothing.

With no policy recorded and none supplied, it stops and says:

```
switchyard: mefp has no desktop policy, and every role launch needs one. An
  operator has to choose it for this tenant: it is never copied from another
  project, and Wayland access is never assumed.
switchyard:   headless -- no desktop access for any role:
  switchyard upgrade mefp --desktop-policy headless
switchyard:   Wayland  -- an approved policy scoped to project 'mefp' and tenant
  '<tenant>', carrying this tenant's own recorded consent:
  switchyard upgrade mefp --desktop-policy FILE
switchyard: stopping before any phase, so mefp is not declared ready and no pane
  restart should follow. Nothing was changed: no artifact, account, release,
  access grant, board, listener or role session.
```

A dry run says the same thing, as what the upgrade would do. Both exit non-zero,
because an upgrade that can only finish into a tenant that cannot start is not a
finished upgrade, and every wrapper reading the status would otherwise report it
as one.

A policy that is supplied or recorded is validated against this project and
tenant at the same point, so a borrowed one — another project's, another
tenant's, or a Wayland grant without its own approved consent — is refused before
anything changes, not after the manager repair has already run.

## Once chosen

The existing path already did the rest correctly, and is unchanged: the choice is
written into the tenant configuration and into `desktop-policy.json` beside it;
regeneration merges that file back in, so later phases keep it; a Wayland grant
is installed and verified from the tenant's side; and a later `switchyard start`
launches without being asked again. A rerun with no flag keeps the recorded
policy.

## Readiness says it

The upgrade's phase table now has a desktop line:

```
  desktop     operator ready        role launches use the headless policy recorded for mefp
```

It describes the policy the preflight validated rather than reading the file,
because a dry run records nothing: read from the file, a dry run handed a valid
policy reported the tenant as *missing* the very policy it had just been given.
In a dry run it reads "would use the … policy supplied for mefp; a dry run
records nothing".

## A failed install is said, not dumped

Testing the failure path found that a Wayland install which cannot reach the GUI
session escaped `switchyard upgrade` as a raw `DesktopAccessError` traceback. The
rollback had already run, so nothing was left half-done, but a traceback reads as
a crash in the middle of an upgrade. It is now a sentence: the policy could not
be installed, nothing was recorded, the previous policy is back, and since this
runs before any phase no board, listener or role session was touched.

## Verification

`tests/team_launcher_legacy_desktop_policy_upgrade_test.py`, 67 checks, driving
the real upgrade entry point against a tenant generated by the real provisioning
code, with only host commands, the privileged Wayland install and its tenant-side
verification simulated:

- a legacy tenant is told before any phase runs — both choices named as commands,
  not declared prepared — and **nothing changed**, asserted as every file under
  the tenant byte- and mtime-identical *and* no host command run at all;
- headless is recorded in both places, grants nothing, and lets `start` launch;
- an approved Wayland policy is installed once, for this tenant, verified from the
  tenant's side, recorded, and lets `start` launch;
- another project's or another tenant's policy, and an unapproved grant, are
  refused with nothing changed;
- a dry run names both choices, says it is a dry run, and grants and writes
  nothing — and, given a valid choice, reports ready on it rather than missing;
- a failed install leaves every file as it was, starts or stops nothing, records
  nothing, and says so in a sentence;
- a rerun needs no second choice and keeps the policy;
- the readiness table's own contract, including the missing case.

Mutation: 10 mutants, no survivors.
